# 《数字经济一本通关》

0258 数字经济考研辅导教材，全书 15 章，LaTeX（ctexbook + XeLaTeX）排版。

## 快速开始

- 环境：TeX Live（需 `xelatex`）
- 编译：`./build.sh`，双遍生成目录，要求 **0 错误**、Overfull 不新增（全书基线 1 处，第 1 章 4.86584pt）
- 目录结构：
  - `main.tex` 主文件，`sections/` 各章源码（1--15 章 + 前言）
  - `教学大纲.md` 知识点覆盖基线；`参考书对照表.md` 考点审计
  - `CLAUDE.md` 全书书写与审改标准（AI 辅助修改时的项目指令）
  - `试读版/` 独立试读版工程

## 协作规范（必读）

### 动手前

1. **先读 `CLAUDE.md`**：全书 15 章统一的书写与审改标准，修改任何章节前对照其检查清单执行。它不是给 AI 的专属文件，对所有协作者同样有效。
2. **先读 `教学大纲.md`**：大纲列出的知识点必须全覆盖，未列的不臆造；【专硕·核心/扩展】【学硕·热点】标注要一致。

### 分支与合并

- `main` 只保留可交付状态：**不要直接 push main**。
- 任何改动开功能分支（如 `ch10-derivation`），合并走 Pull Request。
- 提交前本地 `./build.sh` 双遍 0 错误、Overfull 数量不增加；PR 描述注明编译检查结果。
- 建议仓库管理员开启 main 分支保护（require PR + 至少一名 review）。

### 章节分工与冲突规避

LaTeX 源码的合并冲突极难解（无行级语义），这是本书协作的第一风险点：

- **同一时间段，一个 `.tex` 文件只由一人修改**。改别人的章节前先认领并沟通，不要"顺手"改动他人章节。
- 改动若影响跨章内容（承诺句式"第 N 章详述"、章首/章末衔接句、共享数据），在 PR 描述里列出涉及章节，并知会对口章节的负责人。
- 修改章首 `examguide` 核心考点时，**必须同步**章末 `chapterbox` 考点清单。
- 一次 PR 聚焦一章，改动跨章时拆成多个 PR。

### 提交规范

- 一提交一改动；message 用「章节号 + 动词 + 对象」格式，如 `10.数字金融：改写 10.3 推导框`。
- 涉及数据的改动在 message 里注明来源（机构、年份、口径）。
- 不改与本次任务无关的相邻内容，无关问题另提 issue。

### 内容红线（摘自 CLAUDE.md，完整清单以该文件为准）

- **数据三要素**：机构、年份、口径；不确定就模糊化（"约/超/近"），禁止编造。
- 推导框只放数学，经济解释、实证、案例一律在框外正文；每个 subsection 先有 2--3 句帽子段。
- 破折号（——）每章 ≤10 处，新增内容一律用冒号/逗号。
- 编译产物、备份文件（`*.bak-*`）、本地设置不入库（见 `.gitignore`）。

### AI 辅助修改

用 Claude Code 等工具修改时，把本仓库作为工作目录即可：`CLAUDE.md` 会自动作为项目指令生效，工具会按同一套标准执行。但 **AI 生成的改动仍需人工复核**：编译、数据核验、检查清单（帽子/推导框/mn 位置/考点同步）在合并前逐项确认，PR 是复核的关口。

## 仓库内容约定

- 只提交源码与文档；PDF 与 LaTeX 中间产物不入库，本地 `./build.sh` 生成。
- 参考书（李三希《数字经济概论》）OCR 全文不入库（版权原因），本地保留于 `references/`。
